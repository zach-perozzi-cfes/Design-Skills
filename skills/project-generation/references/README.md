# Reference index

Every reference file for `project-generation`, with its status. Update the status column as material is filled in.

| File | Purpose | Status |
| --- | --- | --- |
| process/intake-questions.md | Questions asked at kickoff | blueprint |
| process/project-lifecycle.md | Phases, gates, milestones | blueprint |
| standards/naming-conventions.md | File, folder, and ID rules | blueprint |
| standards/deliverables-checklist.md | Contents of a complete package | blueprint |
| examples/ | Worked example packages | empty |

Status values: `blueprint` (structure only), `draft` (content present, unreviewed), `approved`.

## Conventions for adding material

- One topic per file. Split a file once it passes ~300 lines.
- Start each file with a one-line statement of when Claude should read it.
- Put long tables and lookups in `data/spreadsheets/`, not here. Reference files hold rules and explanations.
